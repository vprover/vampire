# Additional clause replay certificates

With `--proof tstp-ac` (which requires `--proof_extra replay`), or
`--proof tptp --replay on`, the following rules
now emit substitutions using the original proof parent names:

- `extensionality_resolution`: both parent banks and both resolved occurrences.
- `forward_literal_rewriting`: both parent banks, the rewritten occurrence,
  and the resolved occurrence from each parent.
- `unit_resulting_resolution`: one composed substitution per parent position,
  including unit parents whose variables are instantiated by later resolutions.
- `backward_subsumption_resolution`: the side-parent matcher and the removed
  occurrence in the main parent, just as for forward subsumption resolution.
- `subsumption_equality_resolution`: the unifier of the removed disequality,
  composed with the renaming needed to retain the printed survivor names.
- `constrained_resolution`: both parent banks, both resolved occurrences, and
  the additional disequalities generated by abstracting unification.
- `condensation`: the substitution for the parent and the removed occurrence,
  for both fast and general condensation.
- `backward_demodulation`: independent main/side banks, the rewritten
  occurrence, and the source equality and instantiated rewrite terms.
- `forward_subsumption_demodulation`: the same rewrite certificate, with the
  side substitution recorded directly from the engine's context/subterm matcher.
- `backward_subsumption_demodulation`: the same certificate, using the existing
  backward engine's context/subterm matcher, with the main parent first and the
  source equality's side parent second. The rewritten literal stays in place
  in the natural conclusion; selection permutations produce a following AC node.
- `inner_rewriting`: the negative source equality and every changed occurrence.
- `constrained_superposition`: both parent banks, the source equality,
  rewritten occurrence, and generated disequalities.

The existing format remains `unifier([subs(fParent,[b(X0,term),...]),...])`.

With `--proof_extra replay`, old `CNF::clausify` records a certificate
in `ProofExtra` for a clause-shaped formula parent
(a universal prefix followed by a disjunction of literals). With replay
enabled, `cnf_transformation` prints
`binder_mapping([b(X0,X0),...]),literal_permutation([...]),swapped_equalities([...])`.
The binder mapping lists parent variables in their declared prefix order and
maps each to its conclusion variable; this clausifier preserves variable
identifiers even when the displayed conclusion's binder order changes.
Permutation entry `i` is the zero-based occurrence index, in the printed
instantiated parent's left-to-right literal order, for conclusion literal `i`.
Duplicates consume separate occurrences. `swapped_equalities` lists zero-based
conclusion indices whose equality sides reverse the instantiated printed
parent's sides. Empty lists and identity mappings are explicit.
The certificate is captured at clause creation, before selection; printing
only accounts for the final literal order and orientation. It does not replay
clausification or search variable assignments. General formula clausification,
vacuous binders and NewCNF are outside this certificate's current scope.

Substitution entries are in parent-position order. Repeated occurrences of the
same parent name denote distinct variable banks. For unit-resulting resolution,
`resolved_literals([literal(fMain,i),literal(fUnit,0),...])` is a list of pairs
in the same order as the unit-parent banks.
Unit-resulting replay covers ordinary unit and empty conclusions; answer-literal
synthesis is not reconstructed by this addition.

Constrained resolution adds
`constraints([disequality(sort,left,right),...])`. These are ordinary general
terms in the TPTP annotation, not extra proof premises. Their order is the
constraint-prefix order of the natural conclusion. Terms use the printed
conclusion's variable names, just like substitution values.

AC cores instantiate the original parents, delete the indicated occurrences,
and retain the order of the other literals. Literal rewriting replaces its
occurrence in place. Constrained resolution prepends the recorded constraints.
An AC node is emitted only when this order differs from the displayed clause;
equality orientation reversals do not introduce symmetry nodes.

Rewriting adds `rewrite([equality(literal(fParent,i)),from(term),to(term)])`.
These terms are instantiated in conclusion names; for constrained
superposition, `from` is the rewritten target (which can differ from the source
equality's left side until the constraints are discharged). Multiple changed
occurrences use `rewritten_literals([literal(...),...])`, while a single one
keeps `rewritten_literal(literal(...))`. Constrained superposition appends its
constraints after the parent tails, unlike constrained resolution's prefix.

Preprocessing bridges retain the natural result before selection:
general splitting (both the remainder and named component), inequality
splitting, equality-proxy replacement, definition unfolding, and
equality-proxy axioms. Each of these transformations has a lightweight recording
hook at its result-creation site. There is no Clause-level hook or separate
implementation of the preprocessing transformations. Each call site gates the
hook on the replay proof-extra status, which tstp-ac requires. The recorded
data is just shared literal pointers. Definition unfolding
preserves its existing full proof-extra data alongside that natural result.
Split component definitions precede their `cnf_transformation` core; any AC
node follows that core. General-splitting inferences retain the original main
parent and the split definition (`fN_D`) parents.

With `--proof_extra replay`, `Splitter` captures conversion data directly in
`ProofExtra` while SAT names and definitions are live.
`InferenceRecorder` formats that captured data alongside its other proof certificates.
For `tstp-ac` (including the `tptp-ac` and `tptp_ac` aliases), SAT conversions
of `theory_tautology_sat_conflict` clauses include
`avatar_map([map(literal(fOrigin,i),positive(splName),fDefinition),...])`.
Negative occurrences use `negative(splName)`, not a negated formula inside the
annotation. Indices are zero-based positions in the original, printed FO
clause, independent of SAT sorting. Every source occurrence is recorded,
including duplicates. Each referenced AVATAR definition is also a conversion
parent, following `fOrigin`, once per distinct definition, and is included in
the printed proof DAG. The theory axiom itself remains parentless. Ordinary
conversions whose FO origins already contain AVATAR names, and plain `tptp`
output, retain their existing annotations. No EUF explanation is added.


The recording responsibilities are split as follows:

- `ClausificationRecording` captures the old CNF parent before selection:
  explicit binders, implicit free variables, printed literal occurrences and
  equality orientations. The annotation printer later consumes occurrences
  to describe the final clause permutation. It does not reconstruct a general
  clausification proof or infer a substitution.
- `Rectify` captures the raw scoped renaming while its binder bindings are
  live. `InferenceRecorder::recordRectification` composes it with the sorted
  binder order, following `leancheck`'s `InferenceRecorder::rectify`. TPTP
  recording additionally retains declared binder orders and fully removed
  scopes, since it serializes the certificate rather than printing Lean code.
- `InferenceReplayer` dispatches rules and temporarily indexes the recorded
  parents. It restores their stores and ages and scopes the reconstruction
  flag. `SimplificationReplay` handles literal rewriting and subsumption
  resolution directly from the recorded main and side parents.
- `InferenceRecorder` validates parent occurrences, variable renaming and
  literal multiplicities. Substitution values use conclusion names; variables
  occurring only in eliminated literals get fresh names shared across banks.

Debug CMake builds register `InferenceReplay` and `SMTCheck` with CTest. The
SMT tests use Z3 to validate separate demodulation banks, renamed conclusions
and eliminated variables of different sorts.

# Higher-order certificates

## Term syntax

In higher-order problems every annotation term other than a variable is
wrapped in `$thf(...)`, including sorts (`disequality($thf(i > i),...)`),
substitution values, rewrite terms, witness dependencies and Boolean case
terms. Generic TPTP annotation terms cannot contain lambdas, `@` or arrow
types. Variables are printed bare, using the clause names of the printed
parent (substitution keys) or the printed conclusion (everything else).
First-order output is unchanged.

Vampire stores lambdas nameless (de Bruijn). Each `$thf` term names its own
binders `Y0, Y1, ...`; these names are local to that term and never refer to
clause variables. Types of binders are always printed.

## Beta/eta convention

Certificate terms are printed exactly as Vampire built them. Applying a
substitution is syntactic and is not followed by normalization, so a
substitution value applied under a flexible head yields a beta-redex: the
conclusion and the `from` term of the corresponding rewrite contain e.g.
`p @ ((^[Y0 : i > $o]: (a)) @ p)`. Whenever Vampire normalizes a clause it
does so in a separate `beta-eta_normalization` step. A checker must
therefore compare instantiated parents, rewrite terms and conclusions modulo
beta-eta conversion (and alpha-conversion of the nameless binders).

## Rule names

Rule names that are not TPTP lower words are quoted, e.g.
`'flex-flex_simplification'`, `'beta-eta_normalization'`,
`'and_proxy_clausification_(simplifying)'` and
`'Hilbertian_choice_axiom_instance'`. AC core identifiers derived from rule
names replace such characters by `_`, e.g. `f12_vh_flex_flex_simplification`.

## Constraint order

`constraints([...])` is printed for `constrained_resolution` and
`constrained_superposition` even when empty. Its entries are in the order in
which the abstracting unifier produced them, which is also their order in the
natural conclusion: a prefix for constrained resolution and a suffix (after
both parent tails) for constrained superposition. Higher-order constrained
superposition is replayed with the higher-order superposition engine, so its
substitution is Vampire's selected unifier, not a reconstructed one.

## Occurrence selectors

`rewrite([equality(...),from(s),to(t),occurrence(n)])` replaces only the
`n`-th (zero-based) subterm of the selected literal equal to `s`. The literal
arguments are traversed left to right; a node is visited before its
arguments, and an application's function before its argument (Vampire's
`f @ a @ b` is `(f @ a) @ b`). A match is counted once and its subterms are
not visited. Lambda bodies are visited; sorts and binder domains are not.
`occurrence(n)` requires a single rewritten literal. Without it, every
occurrence in each rewritten literal is replaced. All of Vampire's rewriting
rules replace every occurrence, so a selector is currently emitted only for
definition unfolding whose result is not the all-occurrences rewrite.

## Rule certificates

Higher-order rules use `InferenceReplayer` and `InferenceRecorder`, just like
first-order rules. With `--replay on`, the original inference engines regenerate
candidates from the recorded parents; only a candidate matching the goal's rule,
parent occurrences and conclusion is accepted. No higher-order certificate is
stored during proof search, and `--proof_extra replay` is not needed for this
recovery. Literal positions are zero-based indices in the printed parent.

Witness replay reuses a Skolem application already present in the goal, recovers
its dependencies in the parent's variable names, and validates the regenerated
conclusion with the common matcher. It creates no new Skolem symbols. Parentless
choice and extensionality axioms are regenerated by their original constructors
and checked against the goal through the same recorder. Substitutions, witness
dependencies and other certificate terms use the matched goal's variable names.
With `--replay off`, these recovered annotations are omitted.

- `primitive_instantiation`, `imitation`, `projection`:
  `unifier([subs(fP,[b(X,$thf(binding))])])`. The conclusion is the parent
  instance (up to beta-eta).
- `leibniz_equality_elimination`: `unifier([subs(fP,[b(X,$thf(predicate))])])`
  with the predicate chosen for the Leibniz variable; the conclusion
  additionally removes the two Leibniz literals and adds the equality.
- `'flex-flex_simplification'`: `unifier([subs(fP,[...])])` mapping every
  flexible head `F : t1 > ... > tn > b` to `^[Y0..]: Z`, where `Z` is a fresh
  variable shared by all heads with final result sort `b`. Vampire checks
  that every literal becomes a reflexive disequality after beta-reduction
  and otherwise prints no certificate.
- `negative_extensionality`:
  `new_symbols(skolem,[sK]),extensionality_witness(literal(fP,i),sK,[D...])`.
  `literal(fP,i)` is the disequality `s != t`; the conclusion replaces it by
  `s @ (sK @ D...) != t @ (sK @ D...)`. `D...` are the parent variables the
  witness depends on, in application order; they may be a proper subset of
  the parent's variables and in any order. A `unifier` records any variable
  renaming between the parent and conclusion; no `binder_mapping` is printed.
- `sigma_proxy_clausification` (a positive `??` or a negative `!!`):
  `new_symbols(skolem,[sK]),quantifier_witness(literal(fP,i),sK,[D...])`,
  with the same dependency convention. A witness reused from Vampire's
  Skolem index is printed without `new_symbols` unless this is its first
  occurrence in the printed proof; its dependencies can then be arbitrary
  (`$thf`) terms.
- `heuristic_instantiation`: `unifier([subs(fP,[...])])` (the type
  instantiation) and `quantifier_instance(literal(fP,i),$thf(t))`: the
  universal proxy `!! @ T @ P` in the literal is replaced by `P @ t`. This is
  not a parent instance, so `quantifier_instance` is a new field.
- `fool_paramodulation` and `cases_simplifying`:
  `boolean_case(literal(fP,i),$thf(s),true|false)`. Every occurrence of `s`
  in the literal is replaced by the given constant, and `s = $false` (for
  `true`) or `s = $true` (for `false`) is added.
- `'Hilbertian_choice_axiom_instance'` (parentless):
  `inference(rule,[choice_axiom(c,$thf(P),X)],[])` for the clause
  `P @ X = $false | P @ (c @ P) = $true`. For Vampire's builtin choice
  operator (`--choice_ax`) the first printed use is preceded by
  `new_symbols(choice,[c])`. An input symbol recognized as a choice operator
  (`--choice_reasoning`) gets no `new_symbols`: it is justified by its input
  choice definition, which Vampire deletes and does not link.
- `functional_extensionality_axiom` (parentless, `--func_ext axiom`):
  `inference(rule,[new_symbols(extensionality,[d]),extensionality_axiom(d,F,G)],[])`
  for `F @ (d @ F @ G) != G @ (d @ F @ G) | F = G`, with `new_symbols` only
  on the first printed use.
- `definition_unfolding` by a single definition (listed once per unfolded
  occurrence): `unifier([subs(fMain,[]),subs(fDef,[...]),...])`, one bank per
  parent position, `rewritten_literal(s)` and
  `rewrite([equality(literal(fDef,0)),from(..),to(..)[,occurrence(n)]])`.
  Several definitions, nested unfolding or several instances of one
  definition get no certificate.

The builtin choice and difference operators are polymorphic in Vampire;
their certificates name the symbol and leave the type instance implicit.
The builtin choice operator also prints as raw `@@+` inside formulas.
